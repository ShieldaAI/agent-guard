# Agent cartography expansion

This is the implementation contract for the P1 inventory expansion. All new
records are read-only observations from a company-enrolled host. They never
grant execution authority. Core inventory version 1 and manifest version 1
remain readable. Manifest version 2 is closed and bounded; unsupported versions,
extra fields, invalid references and unsafe downgrade attempts fail validation.

## Manifest version 2

Keep all version-1 top-level fields and arrays. Set `schemaVersion: 2` and add
required `authorityId`, `owners` (maximum 1,000) and `credentialReferences`
(maximum 1,000). All records inherit the exact source/tenant, authority, manifest
ID/revision and observation time. Existing 2 MiB/200,000-value manifest and
8 MiB snapshot limits remain enforced.

Required additions to version-1 records:

| Record | Additional fields |
| --- | --- |
| Agent | `purpose: string|null`, `lifecycleState: active|inactive|retired|unknown`, `ownershipStatus: assigned|unassigned|unknown`, `ownershipSource: string|null` |
| Deployment | `runtimeRef: opaque|null`, `workloadGeneration: string|null`, `buildRef: opaque|null`, `bindingAuthority: string|null`, `credentialReferenceIds: opaque[]` (maximum 32) |
| Resource binding | `displayName: string`, `ownerId: string|null`, `ownershipStatus: assigned|unassigned|unknown`, `ownershipSource: string|null`, `sensitivity: public|internal|confidential|restricted|unknown`, `approvedDestinations: opaque[]` (maximum 128), `dependsOn: binding-id[]` (maximum 128) |

`opaque` means exactly `opaque:` followed by 64 lowercase hexadecimal digits.
Opaque references must be generated by the trusted host within its intended
tenant scope; the catalog does not derive or export credentials. Arrays of
references are unique. Names/purpose are nonsecret display metadata bounded to
256/1,024 Unicode scalar values respectively. Other identifier bounds retain
the existing contract. `assigned` requires a non-null owner present in `owners`;
`unassigned` and `unknown` require a null owner. Unassigned is an explicit host
assertion; missing old metadata is unknown. `dependsOn` names other existing
resource bindings and forbids self references; only relationships whose two
endpoints are authorized may be returned to a viewer.

Owner records have exactly `id`, `name`, and `kind: person|team|service`.
Credential-reference records have exactly `id: opaque`, `name`,
`issuerRef: opaque|null`, `audienceRefs: opaque[]`, `recipientRefs: opaque[]`
(each maximum 128), `lifecycleState: active|rotating|revoked|expired|unknown`,
`expiresAt: timestamp|null`, and `rotationStatus: current|due|overdue|unknown`.
There are no token, key, secret, credential URL or free-form payload fields.

AWS resource/identity targets retain their version-1 shape and semantics.
Resource bindings may additionally target exactly
`{provider: 'host', id: opaque, name: string, kind: service|repository|database|queue|storage|other}`.
These support `scope: exact|prefix`; host actions are bounded nonempty identifiers
(maximum 128), with no inferred cloud-policy mapping. Execution identities remain
the existing static AWS/dynamic/unknown contract; a runtime's opaque reference
and its host binding authority provide generic deployment identity provenance.

The snapshot envelope remains version 1 and its embedded manifest accepts exactly
version 1 or 2. Publication must reject a v2-to-v1 manifest downgrade for the same
source generation. New manifest contents require a higher revision, including a
v1-to-v2 transition. Credential/catalog set ordering must not change the semantic
manifest hash. An older collector fails closed on v2; it does not strip fields.
Hash compatibility retains the existing serializer: array set ordering and
observation time are normalized, but this is not general numeric JSON
canonicalization. Use the SDK serializer consistently; hand-written numeric
spellings such as `2.0` versus `2` can cause a safe same-revision content conflict.
Existing stored version-1 hashes are not silently rewritten.

## Projection and query contract

Add projection-local `GuardOwner` and `GuardCredentialReference` nodes, with
`G_OWNED_BY` (agent to owner), `G_RESOURCE_OWNED_BY` (resource binding to owner), `G_USES_CREDENTIAL` (deployment
to reference), and `G_DEPENDS_ON` (resource binding to resource binding) edges.
Properties use snake_case versions of the manifest names; native IDs are
`owner_id` and `credential_id`. Common host properties add `authority_id` and
`manifest_schema_version`. Host external resources use `provider`, `kind`,
`host_resource_id`, and `name`; they never join AWS provider nodes. Their stable
native identity uses provider plus opaque ID, not the mutable display name;
conflicting definitions of the same host resource ID are rejected. Keep raw
relationship-ID arrays out of query properties so hidden endpoints cannot leak.

Indexes and neighborhoods remain company/tenant/team scoped before counting,
filtering, paging or comparing. Add owner/resource browsing and resource-to-agent
navigation. Add offset/limit paging to indexes with deterministic ordering and
authorized totals. Agent details expose structured ownership, deployment,
permissions, resource, connection, credential and relationship evidence. Graph
visualization is supplemental; bounded/paged structured evidence must remain
usable when a whole graph exceeds its display cap.

Retain existing query operations and response fields. Extend `get_changes` with
agent/resource/change-kind filters and bounded safe before/after fields,
relationship additions/removals and affected visible agents. Compare retained
authorized snapshots only. A relationship or declared grant change is not proof
of effective access gain/loss. External IAM policy history, request-time decisions,
approval events and backend receipts remain explicitly `not_collected`; existing
request-time gates and current policy candidates keep their distinct evidence
types. No history view may silently imply those event streams were collected.

## Verification and UX

Exercise v1 compatibility, actual v2 exporter-to-collector-to-Neo4j-to-Map flow,
source/version fences, duplicate/reference/bounds failures, immutable inputs,
credential redaction, generic/AWS separation, ownership transfers, hidden teams,
shared resources, relationship-only changes, missing baselines and no execution
effects. Test installed packages/schemas and meaningful normal/refusal paths.

Use plain labels for assigned/unassigned/unknown ownership, declared permissions,
mapped policy candidates, freshness and missing collection. Provide accessible
tables and relationship lists alongside focused graphs, empty/error/retry states,
keyboard/mobile navigation and Chromium/Firefox/WebKit accessibility checks.
