## Prepared changes since alpha.3

- Company-operated Agent Ops: standard OIDC, exact immutable approval review,
  durable conditional ticket effects, explicit unresolved outcomes and
  receipt-only recovery without automatic redispatch.
- Private onboarding, add-only company ticket imports, reviewed finite capacity
  settings, paginated lists, setup checks, operational status, bounded metrics
  and minimized activity snapshots.
- Reviewed retirement and encrypted company-history compaction; bounded recovery
  closure, reserved capacity for interrupted compaction, independent witnesses
  and exact-current recovery mirrors. Offline key escrow, rotation, retirement,
  backup and restore preserve authority rather than resetting it.
- Agent Map and Cartography catalogs for agents, owners, captured deployments,
  declared permissions, host-bound resources, opaque credential references,
  relationships and retained before/after changes. Paged detail remains usable
  without rendering a large graph. Evidence freshness and missing event streams
  remain explicit.
- TLS/custody startup enforcement, Linux deployment checks, three-engine browser
  and accessibility workflows, dependency inventories and expanded installed
  package/upgrade/recovery checks.
- Fresh, bounded inventory projection in a trusted worker, with verified teardown,
  detached keys, MCP lifecycle rechecks and bounded transfers. Scoped Map queries
  omit irrelevant planning branches while preserving tenant/team/history fences;
  startup retries bounded connection-acquisition timeouts within the existing deadline.

All five public npm workspaces target `0.1.0` with exact matching internal
versions. The intended distribution tag is `latest`; historical `alpha` tags
remain historical. The private React/Cytoscape viewer is built from source and is
not published. Python Cartography keeps its separate `0.1.0a1` source-package
version and deployment process. This first non-prerelease label does not promise
a 1.x API compatibility or long-term-support policy.

## Supported boundary and upgrade

The intended production profile is one Linux owner with company-owned data,
OIDC, TLS, local durable storage and independent recovery custody. It does not
provide HA, distributed quotas, a live Jira/Linear connector or universal model
resistance. Ordinary handlers trust their host. Windows Docker isolation and
unknown company/provider installations require their own acceptance evidence.
Automated browser checks are not a representative human usability study.

Follow the [deployment runbook](../../deployment/production/README.md) and
[upgrade/rollback procedure](../../deployment/production/upgrades.md). New ledger
schemas deliberately reject unsafe downgrade to alpha.3; retain the actual
alpha.3 upgrade fixture and never reset authority to bypass the fence.
See [release instructions](../releasing.md) for the gated publication sequence.
