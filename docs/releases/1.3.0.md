# Agent Guard 1.3.0

A new package, `@shieldaai/agent-guard-check`, scans a repository's AI-agent configuration:
it shows what each agent can do, flags authority it does not need, and on a pull request
reports only what the change made worse. The core gains one read-only method,
`guard.describe()`. All seven packages move to 1.3.0 together.

## Why

Agent Guard enforces limits at run time, but most agent authority is granted in files long
before anything runs: a `bypassPermissions` mode in `.claude/settings.json`, an unpinned MCP
server in `.mcp.json`, a workflow that lets anyone's issue comment start an agent holding a
write token. Those files change in ordinary pull requests and are rarely reviewed as security
changes. 1.3.0 adds a scanner that reads them, explains the resulting authority per agent, and
can gate a pull request on what it widened.

## What is new

### `@shieldaai/agent-guard-check`

- **Agents it reads:** Claude Code (settings, subagents, skills, hooks, plugins and
  marketplaces), OpenAI Codex `.codex/config.toml`, Gemini CLI `.gemini/settings.json`, VS Code
  and Cursor MCP configuration, and GitHub workflows that run `claude-code-action`,
  `codex-action`, `claude -p` or `codex exec`.
- **46 rules** (`AGC-*`) mapped to OWASP ASI01–ASI10, listed in
  [the rule catalog](../../packages/check/docs/rules.md). 34 work on repository files alone.
  8 more use Agent Guard records (`describe()` output, executor inventory snapshots, host
  manifests). 4 use a running Agent Map, read-only, when you ask for live evidence.
- **Pull requests:** `--base <ref>` reports capabilities that grew and findings that are new or
  more severe. `.agc.yaml` and an in-repository baseline are read from the base commit, so a
  change cannot lower its own gate.
- **Outputs:** text, JSON, SARIF 2.1.0, a Markdown pull-request comment and an inventory.
  `--import-sarif` merges other scanners' findings.
- **Policy as code** in `.agc.yaml`: approved MCP servers and hosts, forbidden capability
  combinations, reasoned ignores and severity overrides.
- **Fixes:** `--fix` and `--fix-dry-run` only remove authority or add limits. Each edit is kept
  only if a new scan shows its finding gone and nothing as severe added.
- **Where it runs:** the command line, a GitHub Action (`packages/check/action`), a read-only
  MCP server (`agent-guard-check-mcp`), a Claude Code skill, a pre-commit hook and a container
  image.
- By default it reads files only. It never runs repository code, never starts an MCP server and
  makes no network calls.

### Core

`guard.describe()` returns a frozen list of the registered tools, sorted by name. Each entry
has the fingerprint, approval state and declared safety labels (`readsUntrusted`,
`untrustedContext`, `sendsExternal`; `null` when undeclared). It holds no task, argument or
secret data. See the [API contract](../api-contract.md).

## Upgrading from 1.2.0

Nothing changes for existing code. Move every Agent Guard package you use to 1.3.0. To scan a
repository, run `npx @shieldaai/agent-guard-check@1.3.0`. In CI, pin the exact version: a minor
release can add rules.

## Known limits

- The scanner sees the repository only. Settings outside it (a user's own Claude Code, Codex or
  Gemini settings, managed policy) and what an MCP server does at run time are not visible
  without Agent Guard records or live evidence.
- It does not detect malicious code inside an MCP server, plugin or skill.
- An inline `agc-ignore` comment on a finding the base already had takes effect in the same
  change; protect agent configuration with CODEOWNERS.
- Recall on real repositories is not measured: there is no ground truth. The labeled cases
  measure each rule against configurations written to trip it.
- The limits of [1.2.0](1.2.0.md#known-limits), [1.1.0](1.1.0.md#known-limits) and
  [1.0.0](1.0.0.md) still apply.

## Before this release

The package was merged in pull request 70. Two independent reviews before publishing found
17 defects, all fixed in the release pull request with a regression test for each:

- A pull request could lower its own gate through `.agc.yaml` or the baseline.
- A repository's `.agc.yaml` could name any CI secret to send to a URL it chose.
- The GitHub Action could run a scanner committed in the pull request.
- Names from repository files could inject GitHub workflow commands or Markdown.
- Detection gaps let some dangerous configurations pass: multi-line and `npx` agent commands,
  Codex short flags, bot tokens, loosely versioned MCP packages, and severity increases under
  `--base`.

The [changelog](../../CHANGELOG.md) lists each one.

## Verification

- `npm run check`: every test passes, except the Docker, Linux-only and Windows-only cases that
  this platform skips. The packed packages pass in a clean project, including both
  `agent-guard-check` executables.
- `npm run bench:check`: 123 labeled cases over all 46 rules, precision and recall 100%.
- `npm run bench:check -- --real`: the 32 pinned public repositories reproduce the reviewed
  findings.

CI and CodeQL must pass on the pull request and on the merge commit before publishing
([releasing](../releasing.md), step 5).
