# Agent Guard 1.5.0

Agent Guard Check can now hold every agent to a review record: an owner, the capabilities its
last review approved it to use without asking, and a date by which someone looks again. A date
that passes fails every pull request until the agent is reviewed again. All seven packages move
to 1.5.0 together, as every release does.

## Why

"Give every agent an owner and a review date" was advice the scanner could not check. A review
date in a file is a snooze button: when it comes round, it gets moved like a dependency bump,
and nobody looks at what the agent can do now. 1.5.0 makes the date a gate and puts the agent's
current access in front of whoever renews it.

## What changed

- **`.agc-reviews.yaml`** at the repository root: per agent (by ID, name or defining file) an
  `owner`, a `review_by` date (`YYYY-MM-DD`, UTC) and the `capabilities` it may use without a
  person approving each use.
- **Eight rules**, AGC-REV-001 to AGC-REV-008:
  - the date passed (high; info for the 14 days before): it counts as new in every pull
    request, and neither a baseline nor an inline `agc-ignore` comment silences it;
  - an agent without a record, with `policy.require_reviews: true` (high);
  - an agent that can do more without asking than its record approves (high), so widening
    access means editing the record;
  - a date further ahead than `policy.max_review_days`, default 365 (high);
  - a record that matches no agent, usually a moved agent (high);
  - an owner CODEOWNERS does not name (low);
  - a record that cannot be read (high);
  - a record that approves access the agent no longer has (low), so it cannot come back later
    without the record.
- **Pull-request reports** (text, Markdown, JSON) list every review record the change adds,
  removes or edits: date, owner, what it approves and approved before, and what the agent can
  do now without asking, with what the record does not approve marked.
- With `--base`, the records are read from the change and the limits (`require_reviews`,
  `max_review_days`) from the base, so a pull request cannot loosen its own gate.
- API: `ScanOptions.now`, `ScanResult.reviews`, `ScanDiff.reviews`.

## Upgrading

Nothing to change: without `.agc-reviews.yaml` and the new policy keys, scans report exactly
what 1.4.0 reported. To start, add a record per agent (`agent-guard-check --format json` lists
their IDs and names), then set `policy.require_reviews: true` in `.agc.yaml` once every agent
has one.

## Known limits

- The scanner cannot tell whether anyone reviewed the agent before moving the date. That stays
  with the pull-request approvers, ideally the owner through CODEOWNERS.
- Without `require_reviews`, records are opt-in: deleting one, or moving an agent and leaving
  another at the old path, leaves the moved agent unrecorded without failing.
- Approvals are per capability, not per command: once `exec` is approved, another command that
  runs code does not change the record. The permission rules judge those commands.
- AGC-REV-006 checks that the owner appears in CODEOWNERS, not that they own the agent's files.
- `@shieldaai/agent-map` stays experimental and outside the 1.x compatibility promise.
