# Agent Guard 1.3.1

`@shieldaai/agent-guard-check` reads far more agent configuration and fails closed: what it
cannot parse, follow or model is reported as unknown reach with a finding, not treated as
safe. The other six packages are unchanged and move to 1.3.1 with it, as every release does.

## Why

1.3.0's scanner covered the common Claude Code, Codex and Gemini settings and the usual agent
steps in GitHub workflows. Twelve independent adversarial reviews then showed how a pull
request could still give an agent more reach than the scan reported: a hook that approves
tool calls, a Bash rule whose options run other programs, an agent started from a repository
script, a hand-edited gh-aw lock file, settings moved by an earlier workflow step. 1.3.1
closes every gate-level issue those reviews reproduced.

## What changed in `@shieldaai/agent-guard-check`

- **More agents and formats:**
  - OpenCode, the Cursor CLI and Cursor hooks, Copilot custom agents, Kiro, Agent Plugins.
  - GitHub Agentic Workflows (`.md` sources and `.lock.yml` files, checked against each
    other).
  - Zed, Aider, and VS Code auto-approve settings in `.vscode/settings.json`,
    `*.code-workspace` and dev containers.
  - Agents the scanner does not model are reported rather than ignored.
- **Bash rules fail closed:**
  - a rule is narrower only when every command in it matches a known shape;
  - exact rules are split like a shell, and options that run a program are read;
  - harmless commands (version checks, listings, workspace scripts) are not reported.
- **Hooks are judged like commands.** A hook that answers "allow", or whose decision cannot
  be read, is a bypass and is never counted as a runtime check.
- **Workflows:**
  - agent CLIs are found through quotes, wrappers, `bash -c`, `eval`, repository scripts,
    `npm`, `make`, Taskfile and Dockerfile targets, interpreter files and the Claude Agent SDK;
  - agent actions match under any owner;
  - composite, JavaScript and Docker actions and reusable workflows are read;
  - secrets are found in every expression form, and settings moved by earlier steps or
    `$GITHUB_ENV` are followed.
- **New rules and gates:**
  - AGC-CFG-001 reports settings it does not model.
  - AGC-CFG-002 reports configuration it could not read: too large, linked out, unparseable,
    case variants, a truncated walk.
  - AGC-COV-001 is high when an agent can run code and send data out with no check.
- **Also new:** `.agc.yaml` `mcp_servers` declarations, `--include-user` for your own settings,
  and a published inventory JSON schema.

## Upgrading

Expect more findings than with 1.3.0, and some new high ones that fail the default gate. Each
names a file, a line and a fix; the rule catalog explains why. With `--base`, only what a pull
request widens is reported.

## Measured

- Labeled cases: 129 over 48 rules, precision and recall 100%.
- 32 public repositories at pinned commits, 191 agents: 178 critical, high and medium findings
  reviewed by hand, 177 true positives (99.4%) under the documented fail-closed reading.
- Recall against independent labels: 68 of 70 agents found, 84% of labelled capabilities
  reported.

## Known limits

The scanner reads files and runs nothing, so a determined author can still hide reach from
it. The package README lists what it does not see, under "What the scan does not see".
