# Agent Guard 1.6.0

Agent Guard Check now looks past the files a pull request shows. It reports when the branch does
not require the code owner's approval, flags MCP servers allowed whole, and runs as a Claude Code
hook on developers' machines, where local and personal settings add to what the repository
reviewed. All seven packages move to 1.6.0 together, as every release does.

## Why

Three gaps, each raised by readers of "agents as code":

- A CODEOWNERS entry only requests the owner's review. "Require review from Code Owners" in a
  ruleset or branch protection rule is what makes the approval required, and it lives in another
  place, so a pull request that widens `.claude/settings.json` could merge with any approval.
- Allowing an MCP server whole (`mcp__postgres`) also allows every tool a later version of the
  server adds. The check skipped this when the server was read-only at scan time.
- Claude Code merges the repository's settings with the gitignored `.claude/settings.local.json`,
  the developer's `~/.claude` settings and managed settings. No pull request shows those, and the
  check saw them only when someone ran it with `--include-user`.

## What changed

- **AGC-GOV-004** (low; info when it cannot tell): CODEOWNERS gives an owner to a file that defines
  an agent, and the branch does not require that owner's approval. `--github-repo owner/name` (and
  `--github-branch`) asks GitHub, read-only, which rules apply. The GitHub Action does this by
  default with the workflow token (input `github-rules`). Classic branch protection is readable only
  with admin access, so without it a protected branch with no ruleset requiring code owners is
  reported at info. On a pull request the finding counts as new only when the change widens an
  agent, adds one or edits a review record. A GitHub error is a warning, never a failed scan.
- **AGC-PERM-002** now flags every identified MCP server allowed whole in Claude Code permissions:
  medium if it writes, sends data out or spends (as before), low otherwise.
- **`--hook`**: run from a Claude Code SessionStart or UserPromptSubmit hook. It compares the folder
  plus the settings Claude Code adds with the files git tracks, as staged, and reports what the
  difference adds at or above `fail_on`. SessionStart shows it and the session goes on;
  UserPromptSubmit holds prompts until the local settings are fixed. The hook's own mistakes and
  failures exit 1 and never block. `npx --no-install @shieldaai/agent-guard-check --hook` is the
  form the scanner does not report as a hook that reaches the network.
- API: `fetchBranchRules`, `GitHubError`, `runHook`, `parseHookInput`; `ScanOptions.github`,
  `ScanResult.modes.github`.

## Upgrading

Nothing to change for existing scans. The Action's new GitHub call can be turned off with
`github-rules: false`. To run the check on every Claude Code session, add the package as a dev
dependency and the hook from the README ("On every Claude Code session") to `.claude/settings.json`.

## Known limits

- The Action's GitHub call is inferred from GitHub's documentation to work with the default token
  (Metadata read); if it cannot, the scan warns and goes on without AGC-GOV-004.
- Who may bypass a ruleset is not visible to the scanner.
- A hook warns or holds; it does not enforce. A developer can turn project hooks off with
  `disableAllHooks`. Managed settings (`allowManagedPermissionRulesOnly`, `allowManagedHooksOnly`)
  are the enforcement.
- The hook does not read agents, skills and commands under `~/.claude`, user plugins,
  `managed-settings.d`, or managed settings from an MDM profile or the Windows registry.
- `@shieldaai/agent-map` stays experimental and outside the 1.x compatibility promise.
