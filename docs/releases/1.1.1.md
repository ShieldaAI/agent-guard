# Agent Guard 1.1.1

A documentation-only patch of `@shieldaai/agent-guard`, `-mcp`, `-scenarios`, `-executor`
and the experimental `@shieldaai/agent-map`. The code, types and behavior are the same as in
[1.1.0](1.1.0.md). All five packages move to 1.1.1 together, as they always do.

## What changed

- **The npm page for the core package** now says what problem Agent Guard addresses before
  it says what it does: agents read text they did not write, a hidden instruction can mislead
  them, and the guard limits what a misled agent can do. It links to the
  [OWASP Top 10 for Agentic Applications mapping](../../README.md#risks-and-which-package-handles-them).
- **The core package description** on npm leads with that outcome.
- **The repository README** points from its problem section to the OWASP table.
- **The release procedure** says to publish from a full clone. npm does not record `gitHead`
  when it publishes from a `git worktree` checkout, which is why
  `@shieldaai/agent-guard@1.1.0` has none.
- **The Python Cartography integration** (in the repository, not on npm) locks `dnspython`
  2.9.2 for [GHSA-vvf4-9x63-8xvv](https://github.com/rthalley/dnspython/security/advisories/GHSA-vvf4-9x63-8xvv).
  None of the npm packages use it.

## Upgrading from 1.1.0

Nothing to do. Changing `1.1.0` to `1.1.1` in your dependencies changes no code. Keep all
the packages you use on the same version.

## Known limits

The limits of [1.1.0](1.1.0.md#known-limits) and [1.0.0](1.0.0.md) still apply; see also
[Support and limits](../support-and-limits.md).
