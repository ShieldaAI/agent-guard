## Protection and recovery

- Check tool scope before trusted parsing and resolution callbacks, reject
  unsupported argument objects, and bound pending policy work. Approval checks
  also reject backward clock movement and revalidate authority before dispatch.
- Constrain workspace file capture against directory replacement and bind each
  approved input version to the exact bytes staged for the guest. Raw inputs and
  signed artifact imports use the same capture boundary.
- Add signed build provenance, sensitive artifact receipts and governed memory
  imports that preserve tenant, source-policy and quarantine checks across reuse.
- Add an optional independently retained SQLite rollback witness. Resume rejects
  a restored ledger that does not match the latest witness. The
  [recovery guide](../guides/ledger-rollback.md) covers provisioning, custody,
  restoration and measured synchronization cost.
- Add verified HTTPS MCP credential sessions and isolated MCP deployment checks.
  Enforce enrolled origins, token lifecycle, metadata bounds and credential
  custody. Restrict additional CA trust to its enrolled origin and retain DNS,
  hostname and private-network checks.
- Add bounded decision traces and redacted exports. Recheck task credentials
  after request-body collection, constrain model dispatch and preserve accounting
  for unresolved execution.

The OpenAI and Anthropic ticket examples now share exact host review, scoped
record resolution and backend receipts. A lost write response stops further
dispatch, and later provider failures retain proof of completed work. The
terminal practice flow displays the tenant, change, version and expiry, defaults
to denial, and requires an explicitly submitted confirmation. See the
[provider workflow](../guides/provider-ticket-workflow.md).

## Operator experience and evaluation

Agent Map clears protected evidence after authentication rejection, expiry and
session transitions. Search failures hide old matches and present an explicit
refresh path. Mobile navigation keeps all views available, and access
explanations show one policy-evidence section with unknown checks retained.
The synthetic demo respects declared bindings. Contrast, accessible evidence
selection and ordinary recovery flows received browser verification.

Offline provider evaluation accounts for useful completion, effects and control
outcomes. Enrolled model trials bind policy, corpus, budgets and planned
denominators. Signed pilot reviews and the operator-study scorer verify complete,
bound evidence and retain unverified states when observations are missing.
Validation CLIs also execute through directory aliases and replace stale results
when validation fails. Guides and blank study inputs are included.

## Deployment boundaries

Protection depends on the trusted host mediating effects, authenticating
reviewers, resolving tenant resources, controlling credentials and enforcing
backend versions and provider spend limits. The durable profile has a single
authority owner. Inventory describes collected evidence and grants no execution
authority.

Native Windows file-capture execution, representative operator studies, paid
model trials, company identity/builder enrollment, independent deployment review
and physical storage/backup validation remain open for their respective
deployments. A rollback witness requires independent custody of the latest
state. Browser automation establishes the sampled functional behavior and
automated accessibility results. Use the
[deployment validation checklist](../protection-acceptance.md#deployment-validation-checklist)
to enroll and verify the actual deployment.
