# Agent Guard 1.6.1

Fixes from an edge-case review of every package. Two of them close ways a pull request could get
past Agent Guard Check, and one closes a gap in the MCP active-content refusal. There are no new
features or options. All seven packages move to 1.6.1 together, as every release does.

## Why

The review tried odd inputs on each package: case and Unicode in names, prototype keys, requests
cut off partway, git's own environment variables, and the paths `--base`, `--baseline` and
`--hook` take through a checkout. Each fix below was reproduced first and has a regression test.

## What changed

### `@shieldaai/agent-guard-check`

- **Baseline outside the scanned folder.** With `--base`, a `--baseline` outside the scanned
  folder (the Action with `path:` set to a subfolder and the baseline at the checkout root) was
  read from the pull request's own files, so a pull request could add its new findings to the
  baseline and pass. It is now read from the base commit.
- **Git config chosen by the command.** `GIT_DIR=`, `GIT_COMMON_DIR=`, `GIT_EXEC_PATH=`, `HOME=`
  and `XDG_CONFIG_HOME=` before an allowed command, `git --git-dir=`, and `GIT_DIR`,
  `GIT_COMMON_DIR`, `HOME` or `XDG_CONFIG_HOME` in settings `env` now count as changing what runs.
  Each lets a committed git config set `core.fsmonitor`, which runs on `git status`.
- **No more failures on every pull request.** With `--base`, unchanged configuration in a folder
  the scan skips (`vendor/lib/.claude`) is no longer reported as new.
- **`--hook` and build output.** Agent configuration in an ignored build folder
  (`dist/templates/.claude/settings.json`) no longer holds prompts. Tracked files there are still
  reported.

### `@shieldaai/agent-guard-mcp`

- The active-content refusal now ignores case in `ui:` addresses and refuses every HTML, XHTML,
  SVG and JavaScript content type, including `text/html+skybridge`.
- A malformed binding (a flag that is not a boolean, a negative or fractional `maxCost`, a
  `measureCost` that is not a function, an unknown `untrustedContext`) fails
  `INVALID_CONFIGURATION` before any network call.

### `@shieldaai/agent-guard` and `@shieldaai/agent-guard-adapters`

- `toolChanges` and `diffToolDefinitions` mark an input schema dropped or replaced by `true` as
  `SCHEMA_LOOSENED`.
- `prepare()` with a request whose `tool` getter throws, or a proxy request, rejects with the
  `GuardError` and reports the refusal to `onDecision`.
- A tool named `__proto__` is kept in `registerApprovedTools` fingerprints and `aiSdkTools`;
  `explainCode` and `modelMessage` no longer read `Object.prototype`.

### `@shieldaai/agent-guard-executor` and Agent Ops

- The path rule refuses the Windows device names `COM¹`-`COM³`, `LPT¹`-`LPT³`, `CONIN$`, `CONOUT$`
  and `CON .txt`, and treats `ẞ`, `ß` and `ss` as one name, as macOS does.
- Agent Ops answers a request body the client abandons with a client error instead of logging a
  service failure.

## Upgrading

Nothing to change. Agent Guard Check may report new high findings for allowed commands that start
with `HOME=`, `XDG_CONFIG_HOME=` or `GIT_DIR=`, or that use `git --git-dir`. If one is intended,
narrow the rule or record a review for it.

## Known limits

- `--hook` reports a developer's own `statusLine` or Notification hook in `~/.claude` as a high
  finding, which holds prompts under UserPromptSubmit.
- A gh-aw `.lock.yml` changed in the same pull request as its `.md` source is judged from the
  source only.
- `@shieldaai/agent-map` stays experimental and outside the 1.x compatibility promise.
