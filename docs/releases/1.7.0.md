# Agent Guard 1.7.0

Agent Guard Check learns two rules readers asked for, reads runner and container commands the way
those programs do, and ships as a plugin for Claude Code, Codex and Antigravity. The other packages
have no changes; all seven move to 1.7.0 together, as every release does.

## Why

Two comments on "Your agent's permissions are already code" pointed at gaps. One: an MCP server
pinned to `npx some-server@1.2.3` still runs new code when one of that package's dependencies
publishes a release, and a Docker tag can be moved to another image. The other: requiring
code-owner review means little if someone on a ruleset's bypass list can merge without it.

Testing the first against 536 public `.mcp.json` files showed that AGC-SUP-001 sometimes read a
runner's option value (`--python 3.12`, a registry URL, a Docker user) as the package, so an
unpinned server could go unreported.

## What changed

### `@shieldaai/agent-guard-check`

- **AGC-SUP-006 (new, low): a pinned MCP server that can still change.** npx, uvx and the other
  runners resolve a pinned package's dependencies again on each fresh install; a Docker image pinned
  by tag can be moved. The fix is a lockfile (a dev dependency started with `npx --no-install`, or a
  locked Python environment) or an image digest.
- **AGC-GOV-004 reports a code-owner requirement someone can bypass (low).** Every rule that
  requires code owners applies at once, so only an actor on every bypass list gets through. Bypass
  lists are readable with an admin token only; with any other token, the Actions token included,
  nothing new is reported.
- **Runner and container commands read as the programs read them.** npm's options come from npm's
  own definitions and npx is read by a replica of `bin/npx-cli.js`; uv's, Docker's and podman's
  options come from their own lists. An option the scanner does not know, followed by a word, makes
  the command unreadable (AGC-SUP-001, high) instead of a guess. npx's rule for running an installed
  copy is followed from the root lockfile, with a semver reader checked against node-semver.
- **MCP server through the default bin.** `agent-guard-check --mcp [root]` starts the read-only MCP
  server, which is what MCP registries run. The package declares `mcpName` for the official MCP
  Registry, where the server's name is `io.github.ShieldaAI/agent-guard-check`.
- **No fetching in partial clones.** The MCP server sets `GIT_NO_LAZY_FETCH`, so comparing with a
  commit in a blobless clone does not fetch from the remote (git 2.44 and later).
- **GitHub Action:** the pull-request comment warns and goes on when the token cannot comment, as on
  pull requests from forks, instead of failing the check. It is also published on its own as
  `ShieldaAI/agent-guard-check-action`, for the GitHub Marketplace.

### Plugin

`plugins/agent-guard-check` is one plugin for Claude Code, Codex and Antigravity: the skill and the
read-only MCP server. Install it with `/plugin marketplace add ShieldaAI/agent-guard` and
`/plugin install agent-guard-check@shielda` in Claude Code, or
`codex plugin marketplace add ShieldaAI/agent-guard` in Codex. Its launcher runs the pinned package
from outside the project, so a repository's `.npmrc` or `node_modules` cannot choose the scanner
that checks it. `plugins/agent-guard-check-skill` is the same plugin with the skill only, for
Anthropic's plugin directory, which accepts local MCP servers and scripts only from verified
organizations.

## Upgrading

- Expect new AGC-SUP-006 findings (low) for pinned npx, uvx and Docker-tag servers. They do not fail
  a run at the default `fail-on: high`.
- Expect AGC-SUP-001 to report a few commands it used to read wrongly, now as unpinned or
  unreadable. In the 536 public configs checked, 16 findings changed, each to the right package or
  image or away from a false one.
- Move the Action pin to the 1.7.0 commit, or use `ShieldaAI/agent-guard-check-action@v1.7.0`.

## Known limits

- The code-owner bypass check needs a token with admin access to the repository.
- pnpm, yarn, bun and pipx document too few options for a full list, so an unknown option there is
  still read as a switch.
- `@shieldaai/agent-map` stays experimental and outside the 1.x compatibility promise.
