# Agent Guard 1.4.0

Agent Map can now show the whole fleet at once: which agents can reach each other, what they
share, how isolated each one is, and what changed in its permissions. Hosts can declare each
deployment's network isolation in manifest v4, and the map shows it. All seven packages move
to 1.4.0 together, as every release does.

## Why

Until 1.3.1 the map answered questions about one agent at a time. A security team also needs
the picture Cartography gives for networks: which agents could pass data to each other, where
two agents share an identity, a credential, a server or a network segment (so nothing keeps
them apart), and what changed since the last snapshot.

## What changed

- **`get_agent_topology`** (Agent Map, read-only, over HTTP and MCP) and a **Topology** tab in
  the viewer:
  - every agent you may see, boxed by source and environment;
  - agent-to-agent links: delegation, handoff, resource dependency and allowed recipient
    (live tasks only), each with its evidence;
  - shared items: MCP servers, cloud identities (one IAM ARN across sources is one item),
    caller principals, credentials, resources and network segments;
  - per agent: isolation for each layer (`shared`, `dedicated`, `dedicated_in_view`,
    `none_declared`, `unknown`, `not_collected`), what it may send out (`allowlisted`,
    `refused`, `none_declared`, `unknown`), paths around the guard, declared network
    isolation, the boundary flag, and its last change between the two retained snapshots;
  - agents removed since the previous snapshot;
  - a compact answer (every status and count, no detail lists) when a large fleet would not
    fit the response limit.
- **Host manifest v4** adds a required `networkIsolation` list: per deployment a segment, an
  egress policy (`none`, `allowlist`, `open`), allowlisted egress targets and a sandbox kind.
  The executor validates it, the Cartography collector projects it onto deployments, the map
  reads it, and Agent Guard Check accepts v4 files.

## Upgrading

Nothing to change for existing hosts: v1 to v3 manifests keep working, and their network
isolation reads as unknown. To have it shown, move a host to manifest v4; the same ledger
revision is accepted, and a later step back to v3 is refused. `get_agent_topology` is a new
operation, so readers and MCP clients see one more tool.

## Known limits

- Everything is declared evidence: a link or a shared item shows that agents could exchange
  data, not that they did. Network isolation is the host's declaration; no traffic is observed.
- The last change compares the two retained snapshots of a source; changes in between and
  their exact time are not recorded.
- A team reader compares only the agents it may see: `dedicated_in_view` says so.
- `@shieldaai/agent-map` stays experimental and outside the 1.x compatibility promise.
