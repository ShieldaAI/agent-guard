# Agent Guard 0.2.0 (draft, not released)

0.2.0 fixes the correctness and availability problems found in the 0.1 review, settles
the core API for 1.0, and adds an explicit executor ledger format. It makes no 1.x
compatibility promise yet. Every item lists the test that proves it.

Not in this line of commits: the CI timing-gate split (`VDuda/ci-timing-gates`, PR #18)
and the release-truth fixes (`VDuda/release-truth`, PR #19) are separate branches.

## Upgrade notes

- **Executor task server HTTP statuses.** Denials now use 401/403/404/409/429/503
  instead of 400, and the body adds `retryable`. Upgrade `ExecutorClient` and the
  server together; an older client reports the new statuses as
  `EXECUTOR_REQUEST_DENIED`.
- **Deprecated root exports.** Core's internal SPI moved to
  `@shieldaai/agent-guard/internal`, and executor areas moved to `/sandbox`,
  `/inventory`, `/pilot`, `/ops` and `/internal`. The old root names still work as
  `@deprecated` aliases until 0.3.
- **Pruned receipts.** `execution()` for a receipt removed by retention returns
  `status: 'PRUNED'` with its `outcome` instead of `INVALID_PREPARED`.
- **Ledger format.** The executor writes `formatVersion` 1 when it opens an older ledger.
  A 0.1 build still opens it but ignores the field; downgrade is not supported.
- **Minimum ledger size.** The `/ops` key tools now refuse a `maxBytes` below 1 MiB,
  matching the executor.

## Known limits

- The single-CPU 250 ms observer stress profile stays unqualified; the observer is
  experimental.
- At 2,000 agents, `list_resources` (10,000 bindings in one sorted listing) still
  exceeds the map work budget; store-side paging is follow-up work.
- Moving request records into company history files is still an offline job.
